# 架构与阶段边界

## 当前架构

`CLI → Library → SQLite + 原件/处理目录`，音频探测与工作副本转换使用 FFmpeg。
`Library.separate → 独立 Python worker → audio-separator → 可替换模型`。
后续 PySide6 界面复用 Library，耗时任务通过后台工作进程执行，不阻塞界面线程。
训练和完整翻唱使用独立模块，不能要求素材管理预先加载 PyTorch。

- `media.py`：文件内容 SHA-256、首音轨元数据、推理工作副本。
- `library.py`：导入、来源、素材列表、处理任务、缓存和报告。
- `worker.py`：分离 API 适配边界，使用指定解释器。
- `cli.py`：可独立测试的开发入口和批量错误状态。

导入先创建临时副本，再对同一份字节计算哈希并读取元数据；数据库写入使用事务。
归档副本和数据库不能形成单一跨文件事务：如果导入被强制终止，可能留下未登记的原件。
再次导入相同文件会验证该副本并补齐记录。临时 `.import-*` 文件暂不自动清理。

任务记录包含素材 ID、模型名、后端版本、输出格式、状态、时间、输出哈希及错误。
分离每次创建独立目录，保留输入工作副本和后端日志；失败结果不会进入成功缓存。
模型文件内容指纹、完整环境清单与模型参数配置尚需补充；同名权重变更后需 `--force`。
目前顺序执行批量任务，避免多个模型同时挤占显存；尚未实现 GPU 显存自动调节。

## 数据与审核边界

`assets.id` 为原始文件完整 SHA-256。`sources` 支持一个文件多条来源。
`jobs` 记录各次处理尝试；已归档文件路径在资料库内用相对路径。
原始素材分类人工指定，所有素材保持 `pending`，当前没有自动入库训练集的通道。

后续增加 segments（原件时间范围）、analysis（指标/方法/版本/置信度）、
reviews（人工结论/备注/时间）、dataset_versions（导出规则与确定的条目清单）。
评分是建议，人工决定才影响训练集导出。数据库升级使用显式 schema 版本迁移。

## 分阶段交付

1. 基础导入、元数据、原件保护、完全去重、报告、独立分离 API。
2. 可解释的基础检测、音频指纹去重、分段、人工复核界面和训练集导出。
3. 对真实素材比较分离模型，补充语音/歌唱分类、音域与置信度分析。
4. 数据成熟后开展训练：歌唱组与歌唱加讲话组，固定测试片段比较听感。
5. 完整桌面翻唱流程、参数试听、分段重做、混音、导出和 Windows 打包。

质量门槛：工程测试验证文件、状态、流程；真实音频试听验证分离和声线效果。
生成测试信号只能用于前者，不能证明音色还原或训练价值。
