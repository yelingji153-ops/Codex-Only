# ACAね AI 翻唱工作台
## GPT Work 项目需求说明书（V1.0）

### 一、项目背景与最终目标

项目名称：**ACAね AI 翻唱工作台**

目标歌手：**ACAね**（ずっと真夜中でいいのに。主唱）

本项目计划使用 GPT Work / Codex 辅助开发一款基于 Windows 的本地 AI 翻唱桌面软件。

核心目标是利用 ACAね 本人的清唱、弹唱及讲话素材，制作尽可能还原其真实音色的专属 AI 声线模型，使用户能够将其他歌曲转换为具有 ACAね 声线特征的翻唱作品。

项目重点：

- 尽可能还原 ACAね 的真实歌唱音色。
- 保留原唱的旋律、节奏、音准和部分演唱细节。
- 重视高音、气声、颤音、真假声转换的自然程度。
- 尽可能减少机械感、电子音、失真和音色漂移。
- 优先使用本地开源技术，不依赖按次付费的云端推理服务。
- 最终形成具有完整图形界面的独立 Windows 桌面应用。
- 架构模块化、便于升级、维护及替换底层 AI 模型。

项目将优先用于本地研究与个人实验。涉及真实歌手声音的训练、合成和传播，应确认素材及声音使用权限；未经授权不得将合成音频冒充为歌手本人演唱或用于商业发布。

目标设备：

- 系统：Windows 桌面端。
- GPU：NVIDIA GeForce RTX 5070 OC。
- 显存：12GB GDDR7。
- 希望尽量利用 GPU 加速人声分离、模型训练和推理。

技术要求：

2. 使用能够支持该显卡的 PyTorch / CUDA 组合。
3. 不直接依赖未经兼容性验证的旧版 RVC 一键整合包。
4. 支持显存占用监测、合理的批次大小及显存不足时的降级配置。
5. 尽量避免训练、推理过程中的显存溢出。
6. 若 Work 在云端运行，须区分云端可执行的开发任务与必须在用户本地显卡执行的训练任务。

暂不假定 CPU、内存及储存容量，后续根据实际环境补充。

### 三、项目整体分期

整个项目分为三个阶段。

**阶段一：训练素材预处理与筛选工具**

这是当前应当优先设计和开发的模块。

目标是将用户收集的大量 ACAね 原始素材，自动整理为可用于后续声线模型训练的高质量数据集。

**阶段二：ACAね 专属声线模型训练**

利用筛选好的素材开展不同训练方案的对照实验，评估音色还原程度与歌唱自然度。

**阶段三：完整 AI 翻唱桌面软件**

整合人声分离、声线模型管理、歌曲转换、试听、音频修饰与导出，形成完整产品。

要求三个阶段的程序、数据格式和接口尽量兼容，避免后续重复开发。

### 四、原始素材的类型和处理原则

用户将持续收集 ACAね 本人录制的素材，主要包括：

**A. 原始纯清唱**

- 没有伴奏的歌唱人声。
- 优先级最高。
- 尽可能保留原始声音细节。
- 适合训练音色、音域和不同歌唱状态。

**B. 吉他或钢琴弹唱**

- ACAね 本人的弹唱录音。
- 包含乐器伴奏。
- 需要先进行人声分离。
- 分离后应重点检查乐器残留与人声细节损失。

**C. 日常讲话**

- 直播闲聊、采访、自然讲话等。
- 用于补充基础音色、轻声、低音与咬字特征。
- 与歌唱素材独立分类管理。
- 不直接假设加入讲话素材必然改善翻唱质量。

**重要处理原则：**

1. 原始素材必须永久保留，不允许自动覆盖。
2. 不要提前对原始素材进行不可逆的降噪、变调、压缩。
3. 允许对工作副本进行人声分离、转换格式和切分。
4. 优先确保音质，而非盲目追求素材时长。
5. 不将分离过度、严重失真的素材直接加入训练集。
6. 记录素材来源、时长、格式和处理历史。
7. 支持后期重新处理同一份素材。

目标是积累覆盖不同音域与发声方式的高质量声音数据，而非单纯堆积大量录音。

### 五、阶段一：素材预处理工具详细需求

开发一个可独立运行、后期可集成至主程序的素材处理模块。

#### 5.1 批量导入

支持：

- WAV
- FLAC
- MP3
- 常见视频文件中的音频轨道

功能：

- 批量导入文件及文件夹。
- 自动读取时长、采样率、声道、格式等信息。
- 记录来源和素材编号。
- 支持断点续处理。
- 防止重复导入、重复处理。

#### 5.2 自动人声分离

研究和比较以下开源方案：

- Ultimate Vocal Remover（UVR5）
- Music Source Separation Training（MSST）
- python-audio-separator

重点评估以下模型架构：

- MDX 系列
- BS-RoFormer
- Mel-Band RoFormer
- 其他经过验证、适合歌唱人声分离的模型

功能要求：

- 批量提取人声。
- 可选择不同分离模型。
- 同时保留原始音频和分离结果。
- 支持对单段素材使用不同分离模型重新处理。
- 可以试听、对比不同模型的分离结果。
- 优先考虑后续通过 Python API 调用，实现自动化集成。

注意：纯净程度不等于训练价值。必须避免为了去除吉他声，而严重损坏歌手的气声、齿音、高音和尾音。

#### 5.3 自动音质检测

分析：

- 背景噪声
- 削波失真
- 静音或无效片段
- 过强混响
- 明显乐器残留
- 音量异常
- 人声不连续
- 可检测的音频处理伪影
- 其他人声干扰

检测结果应提供分项指标和判断依据，不能只输出一个缺乏解释的综合分数。

#### 5.4 素材分级

采用初步四级分类机制：

| 等级 | 含义 | 建议处理 |
|---|---|---|
| A | 优质、干净的人声素材 | 优先加入训练集 |
| B | 基本可用，存在轻微瑕疵 | 人工复核 |
| C | 明显残留伴奏或存在质量问题 | 重新分离或修复 |
| D | 严重失真或缺乏训练价值 | 暂不采用 |

自动评级仅作参考，最终应允许用户手动修改。

#### 5.5 自动去重

检测：

- 完全相同的文件。
- 不同格式的相同录音。
- 同一录音中的重复片段。
- 不同来源、不同压缩质量的相同演唱内容。

建议结合文件哈希、音频指纹及相似度检测。

不自动永久删除重复文件，而是生成重复关系与推荐保留版本。

#### 5.6 自动分类与切分

尝试自动识别：

- 歌唱
- 日常讲话
- 静音
- 其他声音或不确定类别

支持自动切分过长音频，尽量保留完整发声片段，并避免切断歌词、长音、换气或颤音。

低置信度分类应进入人工复核队列。

#### 5.7 音域覆盖分析

针对歌唱素材，估算：

- 不同音高的分布。
- 低音、中音、高音的覆盖。
- 长音片段。
- 不同发声状态下的音高稳定性。
- 数据集可能缺少的音区。

使用图表展示音高分布与素材覆盖情况。

音高检测结果需要标注可信程度，尤其是高音、气声、假声和存在乐器残留的片段。

#### 5.8 人工复核

希望具备一个直观的复核界面：

- 原音频试听。
- 分离后音频试听。
- 不同分离结果对比。
- 波形或音频时间轴。
- 自动评分与问题提示。
- 一键通过、拒绝、重新处理。
- 手动修改分类。
- 用户备注与处理记录。

最终必须由用户决定哪些素材真正进入训练集。

#### 5.9 数据集导出

支持按训练任务导出高质量 WAV 文件，并根据目标模型要求设置采样率、声道和切分规则。

建议形成类似结构：

```text
ACAne_AI_Cover/
├── originals/
├── preprocessing/
│   ├── vocals/
│   ├── separation_tests/
│   └── segments/
├── datasets/
│   ├── singing_A/
│   ├── singing_B/
│   └── speaking/
├── rejected/
├── reports/
│   ├── quality_report.csv
│   ├── duplicates.csv
│   └── pitch_distribution.csv
└── models/
```

文件和文件夹的技术命名可以使用兼容性更好的 ASCII 字符，但软件内展示名称必须为「ACAね」。

### 六、阶段二：AI 声线模型训练

优先调研：

**RVC / Applio**

作为专属训练声线的主要候选技术。

**Seed-VC**

作为免训练转换和其他声线转换路线的对照方案，可根据实际效果评估是否进行微调。

不要先入为主地认定某个模型最优。

#### 训练实验安排

计划至少进行两组对照：

- 模型 A：只使用高质量歌唱素材。
- 模型 B：以歌唱素材为主，加入适量自然讲话素材。

尽可能保持训练设置可比，使用相同的测试歌曲和片段。

重点评估：

1. ACAね 的音色相似程度。
2. 低音和高音的稳定程度。
3. 真假声转换是否自然。
4. 气声、颤音及长音的表现。
5. 咬字清晰度与不同语言的适应性。
6. 人声音质、失真和电子感。
7. 原唱发声习惯是否过度残留。

优先使用成熟的预训练模型进行适配训练，不要求从零训练基础模型。

需要提供：

- 训练参数管理。
- 数据集版本管理。
- 训练进度。
- GPU 显存占用监测。
- Checkpoint 保存与恢复。
- 模型测试及试听。
- 模型版本对照。
- 模型导出和管理。

训练所需素材时长不预设硬性数值，优先验证已有高质量数据能否达到目标。

### 七、阶段三：完整 Windows AI 翻唱桌面软件

最终软件希望具有类似常规音频工具的使用体验。

用户不需要手动运行 Python 脚本、命令行或浏览器服务。

#### 7.1 核心使用流程

1. 打开桌面软件。
2. 导入一首歌曲。
3. 自动分离原唱人声与伴奏。
4. 选择 ACAね 专属声线模型。
5. 根据音域调整人声音高。
6. 试听部分转换结果。
7. 调整参数并生成整首 AI 翻唱。
8. 自动混合转换后人声与伴奏。
9. 导出最终作品。

#### 7.2 主要功能模块

**翻唱工作台**

- 歌曲导入。
- 自动人声与伴奏分离。
- 声线模型选择。
- 音高、转换强度等参数调整。
- 处理进度显示。
- 实时或分段试听（按技术可行性选择）。
- 单段重新转换。
- 全曲音频导出。

**素材管理**

复用第一阶段已开发的功能。

**声线模型管理**

- 导入模型。
- 查看模型信息。
- 版本切换。
- 模型对比试听。
- 模型训练入口。

**音频处理**

- 音量匹配。
- 简单均衡及动态处理。
- 人声与伴奏音量平衡。
- 必要的后处理。
- WAV / FLAC / MP3 导出。

#### 7.3 特别希望实现的功能

**分段重做**

当一首歌曲只有部分高音、人声或咬字出现问题时，可以单独选取对应时间段，修改参数后重新转换。

不必每次都处理整首歌曲。

#### 7.4 界面要求

建议采用：

- Python + PySide6，或其他更合适的成熟 GUI 技术。
- 清晰的侧边导航。
- 现代、简洁、易理解的界面。
- 可视化任务队列。
- 音频波形或时间轴。
- 独立参数面板。
- 错误提示和处理日志。

主要界面包括：

1. 翻唱工作台
2. 素材管理
3. 模型训练
4. 声线模型库
5. 设置

最终希望打包成可以直接启动的 Windows 程序。

### 八、初步技术架构

技术选型为暂定方案，需要根据当前开源生态、兼容性和实际测试调整。

| 子系统 | 候选技术 |
|---|---|
| 桌面图形界面 | PySide6 |
| 音视频读写 | FFmpeg |
| 人声分离 | UVR / RoFormer 系列 / python-audio-separator |
| 声线转换 | RVC / Applio / Seed-VC |
| AI 计算 | PyTorch + CUDA |
| 素材分析 | Python 音频分析工具 |
| 元数据与任务管理 | SQLite / JSON |
| 音频导出 | FFmpeg / 音频处理库 |

开发原则：

- 模块化架构。
- 分离模型可替换。
- 声线模型可替换。
- 不与单一训练框架严重耦合。
- 保留完整处理记录。
- 支持失败重试与断点续处理。
- 尽量利用 GPU 加速。
- 优先保障处理效果、稳定性和维护性。
- 明确第三方项目的许可证与模型权重使用条件。

### 九、质量要求与验收标准

**第一阶段验收**

能够导入一批真实素材，自动完成基本音频检测、分离、切分、去重、分类，并输出可复核的数据集及报告。

必须做到：

- 原始文件不丢失、不被覆盖。
- 自动分离结果可以试听。
- 可进行人工调整。
- 可追踪每段素材的来源和处理参数。
- 低质量素材不会未经复核自动进入最终训练集。
- 能稳定完成批量任务。

**第二阶段验收**

至少能训练并保存一个可用于歌声转换的 ACAね 声线模型，并完成同一测试片段上的不同训练方案对照。

评价重点是听感，而不是只看训练 Loss。

**第三阶段验收**

Windows 用户能够从图形界面独立完成一次歌曲导入、分离、声线转换、试听及导出，无需手动执行命令。
