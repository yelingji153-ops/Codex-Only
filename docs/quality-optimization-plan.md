目标同时满足音色相似、自然、清晰；不以混响遮掩机械感，不把二者当作必选其一。

## 2. 查阅确认与实现问题

### 2.1 索引与 protect

Applio `pipeline.py` 只有在索引存在且 index_rate>0 时才混入检索特征。protect 把无音高帧的检索后特征向原始特征混回；它不是通用去机械感器，也不是直接把原始人声波形混进去。

关闭索引时 feats 与 feats0 相同，进一步调整 protect 理论上不产生实质作用（除浮点误差）。本次不安排 index=0 下的 protect 参数遍历。指数从 0.5 降为 0.2 和完全关闭结果相似，降低了“索引是主要问题”的优先级，但不彻底排除其他输入条件下的影响。

### 2.2 音量与特征采样率

volume_envelope 默认值 1 会绕过原声 RMS 包络匹配。A/B 试听先用一致声道格式、相同时间范围和静态增益匹配响度，保留原文件；不要把随机播放器音量、混响或 EQ 当作比较条件。

若确有动态起伏异常，可单独试 volume_envelope=0.5；这是动态包络实验，不等于单纯响度匹配，也不保证解决机械感。暂不列为第一轮必跑项。

RVC 特征/音高路径采用 16 kHz，生成器输出 40 kHz，是所用实现设计；不能据此推断输出仅有 8 kHz 带宽。把已输出 WAV 改存 48/96 kHz 不会补回细节。不能将 40 kHz 检查点直接按 48 kHz 续训。

### 2.3 素材快照与切分

当前入口对所有已保存片段做 SHA-256 精确去重。它不排除同一原录音重叠时间段的不同切分、不排除不同分离版本，也不判断歌手、和声、混响、乐器残留或音域覆盖。用户已明确授权全部保存批次；不能把旧 pending 字段当作未授权，但应另做质量清点。

工作副本统一 40 kHz 单声道，均衡切分到不超过 3 秒，保留尾段；不足 0.4 秒记录后跳过，无归一化/去混响。此设计不自动判为低质，但需核对有效时长、过短片段比例、强制切点和实际训练采样器是否排除片段。

上游采样器用 WAV 文件字节数/(3*hop_length) 近似长度，当前工作副本是 FLOAT32。长度估计与真实帧数不完全一致；需本机比较分桶保留清单和实际样本数。这是需核查的采样/计数风险，尚无证据证明造成当前机械感，不直接改坏已有实验。

### 2.4 训练与推理可靠性

训练恢复捕获检查点加载异常后可能回落到预训练起点；“开始训练”不等于成功续训。以明确的加载轮数和后续 epoch 为准。

原始训练启动器仍默认总计 100 轮；用户手工命令只把那一次限制到 30 轮。今晚不误用旧启动器续训。后续产品改为明确显示起始轮数、目标总轮数、保存间隔，并提供取消/完成状态区别。

某些推理入口会打印成功字符串，需另外检查输出可解码、时长、非空/非全静音、有限样本与实际模型路径。不能只根据日志一句 successfully 认定音质通过。

## 3. 今晚优先顺序（先用现有模型，不先重新安装）

### A. 固定测试基线与素材清点

1. 保留 10e/30e 模型、索引、旧测试结果，复制最新 G/D 检查点及配置到独立备份目录。保留当前配置，所有试验另存路径。
2. 本机读取 selection.json、prepared-audio.json、skipped-audio.json、filelist.txt、model_info.json，生成片段数/真实时长/源录音数/排除数/重复或重叠范围清单；不能用 209 批次推算准确素材时长。
3. 从 test1、test2 各选固定 15～20 秒，包含平稳元音、齿音/清辅音、气声或高音。另选目标歌手的一段素材做自转换诊断，明确标注它是否在训练中；已见素材不能作为泛化验收。
4. 可取得同一段弹唱原音频时，与上传的分离人声做时间对齐和响度匹配，检查乐器泄漏及人声细节损失。当前用户不在电脑前，无需现在找文件；缺此文件不阻断其他试验。
5. A/B 使用静态增益、统一单声道试听副本、同一时间范围、无 EQ/混响。测同声道 LUFS/RMS，不直接把双声道与单声道 LUFS 数字混比。同步切换并隐藏模型标签后重复试听；评分记录相似、自然、清晰三项及具体时间点，不能只凭更响选择。

### B. 最少量的受控转换

每组仅改一个变量。每段保留输出哈希、模型哈希、索引哈希、全部参数、时长与耗时。

| 编号 | 变化 | 目的 | 后续决策 |
| --- | --- | --- | --- |
| B0 | 30e / RMVPE / index 0.5 / protect 0.33 / pitch 0 | 固定当前基线 | 已有整首可截取对照；小片重跑只检验重复性/分块边界，不混称同一生成结果 |
| B1 | 同 B0，仅换为 20e（须文件存在） | 判断更多训练是否单调改善 | 20e 更好则回选它；不能以训练 loss 最低替代试听 |
| B2 | 同 B0，仅把 RMVPE 换成 CREPE full | 排查音高/清浊音识别导致的失真 | 仅短段；先验证已装 torchcrepe 的模型资源能加载。更慢或首次载入失败时停止，不自动下载新整合包 |
| B3 | 30e 基线用于目标歌手自身的人声 | 检查已接近目标音域/音色时能否自然重建 | 自转换也明显退化则优先模型/数据；自转换好、跨歌手差则重点检查覆盖、音高与泛化。此分支只是定位线索 |

第一晚先跑 B0/B2 与目标声线自转换，B1 能直接复用时加入。不再把所有 index/protect/pitch 值组合扫一遍。此前第一首 index=0 结果已知，无需重复同一测试；第二首已有无索引结果则只补记录。

音高实验改善不代表 RMVPE 普遍较差；失败也不能完全排除训练阶段音高标签问题。若需重提训练特征，必须新建实验目录。

### C. 根据结果选择训练实验

- **换音高提取明显改善：** 固定这项推理设置，再用第二首验证。暂不改变数据和模型结构。
- **30e 比 20e/10e 持续改善、素材审核无明显问题：** 从备份的 30e 续训状态另开同配方分支，以 40/50/60 轮为观察点，先设总上限 60；保持 batch/精度/数据不变以便比较。两次检查无可重复改善或出现退化则停，回选已保存的最佳听感版本。60 不是承诺的最佳轮数。
- **训练素材确有残留/伪影，或自转换明显不自然：** 先选干净子集保留低/中/高音与气声覆盖，从同一预训练权重开启新实验；与全量基线比较。不要把旧“全量模型”在小子集上多训后就声称完成了干净数据对照。
- **同一首多个版本/重叠片段偏多：** 按原录音与时间范围去重，保留可追溯选择；不删除原件。评估集按源录音分组隔离，而不是随机切片划分，避免相邻片段泄漏。
- **清楚的素材和受控续训仍无进展：** 再考虑另一套生成器/声码器方案做小规模对照。更换 HiFi-GAN/RefineGAN 等架构需要匹配预训练和采样率，属于新实验和可能的新下载，不直接加载当前检查点继续。先估下载体积与磁盘需求，再安排。

清洗原则：不对全库再叠一次强降噪/去混响；不把全部弹唱判为废料；不为了分钟数增加混响/和声/其他歌手。归一化只在音量分布证明确有需要时作为独立工作副本实验，不能修复丢失的细节。

## 4. 训练速度优化：质量试验之后再做

当前已实测每轮约 47～71 秒。新增 30 轮可先按约 24～36 分钟加启动/保存开销预算，不承诺固定时间，更新估计以最近完整轮为准。

在模型/数据副本上测试，记录 GPU 名称、torch/CUDA、峰值专用显存、共享显存、样本/秒、首批耗时、稳态耗时、loss/梯度有限性。不能只看任务管理器默认 3D 图或 epoch 用时。

1. 基线：FP32 / batch2 / checkpoint on。
2. 只改 BF16，确认 is_bf16_supported 且实际训练日志启用；不要将 BF16 与更换优化器混为一谈。
3. 如显存充裕，只关闭梯度检查点；先实际前后向验证，无 OOM、无非有限值。
4. 再试 batch4；batch 变化会改变每轮更新次数与学习轨迹，不能声称相同轮数是同样训练量。品质对照先保持 batch2。

每个候选先预热，再量至少 20 个稳态 batch；失败回到稳定配置，不动已保存的原模型，不静默转 CPU。该流程尚未在 RTX 5070 执行，不承诺加速比例。

优先级 P0：模型和输入选择器、试验参数/路径回显、15～20 秒预览、生成后直接试听、同位置等响度 A/B、失败与主动取消区分、自动发现模型/索引。让用户不必粘贴长 CMD、猜文件名。
